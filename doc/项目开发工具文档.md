# 项目开发工具文档

## 1. 文档目标
本文件用于说明 `BrownDust2AutoScript` 仓库中与开发相关的工具链、入口命令、代码生成工具、测试与 CI 约束，方便新开发者快速上手。

## 2. 仓库工具链总览
- Python 主体工程：任务调度、设备控制、OCR、WebUI 后端。
- Electron/Web 前端工程：位于 `webapp/`，独立的 Node.js 工具链。
- 安装/部署工具：位于 `deploy/` 与根目录 `installer.py`。
- 资产与关键词生成工具：位于 `dev_tools/`。
- 配置代码生成工具：`module/config/config_updater.py`。

## 3. 基础开发环境

### 3.1 Python
- 推荐版本：`Python 3.10`（`requirements.txt` 由 Python 3.10 生成）。
- 依赖安装：
  ```powershell
  pip install -r requirements.txt
  ```

### 3.2 Node.js（仅 webapp）
- CI 使用 `Node 16`（见 `webapp/.github/workflows/*.yml`）。
- 进入前端目录后安装依赖：
  ```powershell
  cd webapp
  npm ci
  ```

## 4. Python 侧开发工具

### 4.1 运行入口
- 启动 WebUI 服务（主入口）：
  ```powershell
  python gui.py
  ```
- 启动调度循环（脚本主循环）：
  ```powershell
  python bd2as.py
  ```

### 4.2 安装器与部署配置
- 执行安装器流程（git/pip/adb/app 更新）：
  ```powershell
  python installer.py
  ```
- 仅写入部署配置项：
  ```powershell
  python installer.py --set Branch=dev
  python installer.py --set Repository=https://xxx.git
  ```
- 打印安装器测试输出：
  ```powershell
  python installer.py --print-test
  ```

### 4.3 Python 代码质量工具
- Lint 工具：`ruff`（配置在 `pyproject.toml`）。
- 当前规则要点：
  - `line-length = 120`
  - `lint.select = ["E", "F", "I"]`
  - 排除 `webapp/`、`assets/`、`route/` 等目录
- 常用命令：
  ```powershell
  ruff check .
  ruff format .
  ```

### 4.4 依赖锁定工具
- `requirements.txt` 由 `requirements-in.txt` 通过 `pip-compile` 生成。
- 更新依赖锁文件示例：
  ```powershell
  pip-compile --annotation-style=line --output-file=requirements.txt requirements-in.txt
  ```

## 6. Webapp（Electron）开发工具

### 6.1 目录与架构
- 前端工程根目录：`webapp/`
- 分包结构：
  - `packages/main`（Electron 主进程）
  - `packages/preload`（桥接层）
  - `packages/renderer`（Vue 渲染层）

### 6.2 常用 npm scripts（`webapp/package.json`）
- 开发监听启动（Electron + Vite watch）：
  ```powershell
  npm run watch
  ```
- 构建：
  ```powershell
  npm run build
  ```
- 本地可运行产物编译（非正式发布）：
  ```powershell
  npm run compile
  ```
- Lint：
  ```powershell
  npm run lint
  ```
- Typecheck：
  ```powershell
  npm run typecheck
  ```
- 测试（main/preload/renderer/e2e）：
  ```powershell
  npm run test
  ```
- 格式化：
  ```powershell
  npm run format
  ```

### 6.3 前端质量工具
- ESLint：`webapp/.eslintrc.json`
- Prettier：`webapp/.prettierrc`
- Vitest：`webapp/vitest.config.js`
- Playwright：用于 e2e

### 6.4 Git Hook（webapp）
- 配置：`webapp/.simple-git-hooks.json`
- pre-commit 执行：`npx nano-staged`
- 规则文件：`webapp/.nano-staged.mjs`
  - staged JS/TS/Vue 执行 eslint --fix
  - 按变更包执行对应 typecheck

## 7. Dev Tools（开发辅助脚本）

### 7.1 截图工具
- 文件：`dev_tools/screenshot.py`
- 命令：
  ```powershell
  python -m dev_tools.screenshot
  ```
- 用途：连接设备并快速截图，输出到 `./screenshots/dev_screenshots`。

### 7.2 资产按钮生成
- 文件：`dev_tools/button_extract.py`
- 命令：
  ```powershell
  python dev_tools/button_extract.py
  ```
- 用途：扫描 `assets/` 模板图，生成各任务模块的 `assets_*.py`。

### 7.3 关键词生成
- 文件：`dev_tools/keyword_extract.py`
- 命令：
  ```powershell
  python dev_tools/keyword_extract.py
  ```
- 前置：需要游戏数据目录（脚本默认 `../turnbasedgamedata`）。

### 7.4 路线提取
- 文件：`dev_tools/route_extract.py`
- 命令：
  ```powershell
  python dev_tools/route_extract.py
  ```
- 前置：依赖外部源路线目录（脚本中使用 `../SrcRoute/...`）。

### 7.5 过滤器预设生成
- 文件：`dev_tools/filter_preset_extract.py`
- 命令：
  ```powershell
  python dev_tools/filter_preset_extract.py
  ```
- 前置：根目录存在 `filter.xlsx`。

### 7.6 支援角色模板提取
- 文件：`dev_tools/support_extract.py`
- 命令：
  ```powershell
  python dev_tools/support_extract.py
  ```
- 用途：自动滚动支援列表并生成角色模板图。

### 7.7 兑换码抓取
- 文件：`dev_tools/exchange_code/__main__.py`
- 命令：
  ```powershell
  python -m dev_tools.exchange_code
  ```
- 输出：`dev_tools/exchange_code/codes.json`。

## 9. CI（主要在 webapp）
- 工作流位置：`webapp/.github/workflows/`
- 关键流程：
  - `lint.yml`：eslint + prettier check
  - `typechecking.yml`：`npm run typecheck`
  - `tests.yml`：多平台测试 + e2e
  - `ci.yml`：聚合执行 typecheck/tests/release

## 10. 推荐日常开发流程
1. 安装 Python 与 Node 依赖。
2. 若改配置定义，先运行 `python -m module.config.config_updater` 同步生成物。 
3. Python 侧改动执行 `ruff check .`。 
4. Webapp 改动在 `webapp/` 下执行 `npm run lint && npm run typecheck && npm run test`。 
5. 需要刷新资源模板或关键词时，执行对应 `dev_tools` 脚本。 
6. 提交前确认生成物与源码一致（尤其 `module/config/*` 自动产物）。

## 11. 备注
- 本仓库同时包含运行时代码与大量“生成后产物”，开发时需区分“源定义文件”和“生成结果文件”。
- `deploy/Windows/patch.py` 会在安装流程中对内置环境做补丁（如 requests/uiautomator2），用于提升安装成功率与兼容性。
